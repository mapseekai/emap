# emap 全精度真实数据性能实测

日期：2026-09-20。五份用户提供的本地 GeoJSON，WebGL2 与 WebGPU，各三个视距。

## 结论

三十组主测试均完整执行，但全精度远景性能未达可流畅使用的水平。近景两种 GPU 后端均约 60 FPS；远景 big 两者均不足 1 FPS，百万点 pppp 的 WebGPU 也不足 1 FPS。当前实现的 WebGPU 主线程提交更低，却没有获得更高的主测试帧率。结果只适用于本机当前实现，不说明 WebGPU 理论上必然更慢。

LUCC 的固定远景分项实验中，完整填充约 60 FPS，完整描边约 2.7–2.8 FPS，组合绘制几乎由描边主导。后续应优先定位完整描边与密集点绘制的 GPU 工作；是否具体由顶点处理、重复片元覆盖或驱动路径主导，还需进一步分项测量。本轮不通过恢复 LOD、隐藏描边或减点来改善数字。

## 范围与测量口径

测试的是当前 luma 集成分支的独立 benchmark，不是默认 emap viewer/editor，也不是 luma 版本之间的单变量比较。渲染源码在两组测试期间保持相同，SHA-256 校验结果全部一致。

硬件：Apple M4，16 GiB 内存，macOS 15.6.1；浏览器：Headless Chrome 153；CSS 绘图区 1238 × 450，DPR 1.25，设备绘图区 1548 × 563；四个 luma 包均锁定 10.0.0-alpha.1。测试按 WebGL2 五文件、WebGPU 五文件顺序串行执行，每个文件使用独立浏览器进程；原有 Docker/maptile 等服务未停止，机器不是独占测试环境。

完整导入所有数据，不抽样、不做显示 LOD、不按屏幕尺寸省略要素。保守空间分块剔除保留：近景只提交可见分块，块内保持原始几何。点数与原生 arc 中非零线段数量做独立计数核对。面填充与描边使用不同图元，显示顶点数可能大于 mapshaper 拓扑顶点数。

A/B 使用 Canvas → GPU → GPU → Canvas。每轮预热 12 帧，采样 30 帧；每个视距每个渲染器共 60 帧。以帧序号驱动相同轨迹，期间缩放为基准视图的 1–2.3 倍并伴随平移。全范围/远景/近景指导航轨迹起点，远景为 fit 的 exp(-3.2)，近景为 fit 的 16 倍；不是固定视图测试。单独的 LUCC 分项诊断才使用固定远景。

FPS = 1000 / 平均 rAF 帧间隔，并非 GPU 已完成帧数或操作系统呈现帧数。CPU 指 JavaScript 绘制/命令提交。GPU timestamp 为另行采集的固定视图稀疏样本，未与 rAF、CPU 耗时混合；低帧率条件下有效样本少，保留原始值，不用于估计导航每帧平均 GPU 时间。像素读回和截图均不在 FPS 采样区间。

首次就绪是新页面首次导入与初始全精度缓存准备，含一次 Canvas/GPU 首绘提交；以一秒轮询检测，存在约一秒检测粒度。读取前的 SHA-256 检查已预读文件，因此不是操作系统冷文件缓存测试。

## 抗锯齿核对与反向复测

独立初始化探针读取 WebGL 默认 Framebuffer 样本数为 4，antialias=true；WebGPU 当前源码显式配置 4×MSAA。探针在空场景初始化时运行，不属于性能数据；其默认 300×150 画布尺寸未用于性能测试。主测试画布尺寸以每场景环境字段为准。两种实现的着色器、驱动和呈现路径仍不同，不能将这份结果当作完全隔离变量的 API 排名。

主测试结束后，以 WebGPU → WebGL2 的反向顺序重复加载 points.geojson，每视距每后端 30 帧（未并入主测试的 60 帧）。结果如下：

| API | 全范围 FPS | 远景 FPS | 近景 FPS |
|---|---:|---:|---:|
| webgpu | 31.04 | 3.33 | 60.01 |
| webgl | 60.00 | 6.12 | 60.01 |

反向复测与主测试方向一致，但不代表对全部文件做了多轮统计检验。两份复测同样通过全精度数量、暖导航零上传、原文件不变与资源释放检查。
