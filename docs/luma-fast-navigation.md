# luma 快照导航与保守路径过滤

本阶段在 `luma-benchmark` 与 `luma-vertex-editing` 中提供 WebGL2 / WebGPU 快照导航和保守路径过滤。
源数据仍是原生 mapshaper dataset；原始文件未写入、未上传。沿用既有点聚合选项，本轮全精度测试显式关闭它。

## 从 Canvas 借鉴的部分

`src/engine/rendering/render-scheduler.ts` 在慢帧后复用导航快照；
`src/engine/providers/workspace/render.ts` 以快照变换为基准使用 CSS 平移/缩放，交互结束请求完整重绘。
`src/domain/geo/viewport.ts` 的 arc filter 同时包含包围盒剔除和小 arc 阈值；
`canvas-painter.ts` 还包含半像素吸附与重复屏幕点跳过。

本次仅借鉴快照导航及保守空间过滤，**不复制小 arc 过滤、半像素吸附或逐顶点屏幕化简**。
Canvas 使用其原有屏幕路径处理；同一 dataset 的各后端几何重绘成本分别测量。

## 交互与完整绘制分离

手动平移、滚轮期间，复用最后一幅完成的画面，不逐事件提交原始几何。
鼠标松开后约 160 ms 发起最新视图的重绘；滚轮另外经过 120–140 ms 停止判断。
新画面没有完成前保留快照。新手势优先，不使用累积增量作为快照基准；异步完成时相对最新视图重新计算变换。
快照生成在完整绘制后进行，绝不在每次 pointermove 读取像素。

WebGL 通过 fenceSync + 非阻塞 clientWaitSync 轮询，WebGPU 通过提交完成通知等待 GPU；
随后准备有界的预览位图。不会用 gl.finish 或逐指针像素回读阻塞主线程。
`createImageBitmap` Promise 自身可能先于延迟 GPU 操作完成；初版复测发现首拖停顿，
因此正式实现要求 GPU 完成屏障及预览画布准备后才发布快照就绪状态。

快照的画面分辨率固定。平移可能露出新进入视口的空白区，缩放暂时改变图片清晰度和线宽；
停止后的原始几何重绘恢复当前视图和样式。手势中使用快照变换，停止后按原始精度刷新。
示例暂不实现额外边缘预绘。选择要素后，顶点编辑页暂停快照路径，避免标记随位图缩放或使用旧坐标；
继续使用实时完整绘制及原始几何编辑。该场景在大数据远景下仍可能较慢。

尺寸、DPR、数据/编辑版本、样式、后端、模式变化都使快照失效。旧代次位图到达后关闭，
设备丢失或快照失败时不继续显示旧快照。销毁时释放位图、预览画布、计时器及 GPU 资源。
快照的 `snapshotBytes` 仅估算 ImageBitmap 像素，不含额外 Canvas/合成器/驱动实际内存。

## 复用几何的保守路径过滤

完整路径 Buffer 保持不变。按最多 1024 个连续实例建立源坐标包围盒，包含相邻位置，
查询时再扩大线宽/连接的屏幕余量。仅剔除与视口扩张范围确定不相交的区间。
保留跨越视口而两端位于屏外的线段；闭合路径、反向路径、虚线累计距离和邻接属性不变。
不按屏幕尺寸丢弃短线，不抽点，不改变洞、图斑或边界；面填充继续使用保守分块包围盒，
不会因为轮廓在视口外而删掉覆盖整个视口的大面。

WebGPU 使用 firstInstance，WebGL 复用带偏移的 VAO，均不重新上传坐标 Buffer。
偏移 VAO 每 mesh 最多缓存 32 项，随 mesh 释放。连续区间合并且保持原顺序；
超过 24 个离散区间或保留量超过 80% 时恢复该块完整绘制，以免过量 draw calls。
这是允许多画的保守回退，保留原始几何精度。整个数据都可见时，空间过滤保留完整原始工作量。

界面区分可见块顶点、候选线段、提交线段、屏幕外过滤线段。可见块顶点与过滤后 GPU 实例数分别统计；
闭合/边界填充与描边还可能重复引用同一原始顶点。`omitted` 不用于统计屏幕外安全剔除。
原生 dataset 与既有原始坐标选择、编辑、撤销/重做不变。

## 使用与计时

刷新 `/mapseekai/emap/examples/luma-benchmark/?gpu=webgl` 或 `?gpu=webgpu`。
默认打开“快照导航”和“视口路径过滤”；取消各复选框可分别对照。
`?nav=off` 禁用快照，`?cull=off` 禁用路径区间过滤；`&pointLod=off` 显示全部原始点。
同样开关位于顶点编辑示例。切换 GPU API 仍会重载页面并需要重新选文件。

**页面 A/B 压测始终绕过快照。** 导出报告记录 `navigationMode: full-redraw`，
并分别记录 Canvas/GPU 的几何提交统计。手动快照约 60 FPS 对应快照导航模式，原始 GPU 重绘另行采样。
`lastSubmitMs` 是主线程提交；`lastRefreshMs` 包含 GPU 等待和快照准备，单独 GPU 执行时间需另行采样。
鼠标松开到替换画面还包括防抖和调度，另行测量。rAF 是回调节奏，不等于物理显示器完成帧数。

## 真实数据验证

仅使用授权文件 big.geojson、lucc.geojson、building.geojson、points.geojson、pppp.geojson 做性能验证。
全部导入；两个 GPU API 分别测试完整范围/近景，big 额外测试极远景。PointLod 关闭。
独立浏览器串行运行，CSS 绘图区 1238×450，DPR 1。完整重绘预热 3 帧后采样 12 帧，
指针拖动 30 次，记录 rAF、长任务、指针事件延迟、绘制/上传计数和结束后就绪墙钟时间。
图像读取和截图不放入绘制计时；快照帧率与原始几何重绘单独展示。

完整画面在开启/关闭路径区间过滤下比较像素哈希。额外用 LUCC 原始路径子集做
多 DPR、闭合、反向、线宽、虚线、透明度、颜色顺序、急转角及缩放的逐通道像素回归；
这个子集仅用于功能验证，不作为性能样本。

复现：

```bash
pnpm examples:build
EMAP_BENCHMARK_DATA_DIR="/Users/zhang/Desktop/测试数据" pnpm exec playwright test --config playwright.luma.config.mjs luma-navigation.spec.mjs
```

测试使用独立 4193 端口，结束释放；不操作用户原有 4187 服务。性能明细保留在本地
`test-results/luma-fast-navigation/`，普通浏览器测试输出位于 `test-results/luma-browser/`。
默认渲染器迁移、全量静态 big 高帧率、选中编辑状态的独立快照背景合成仍未由本轮实现或证明。
