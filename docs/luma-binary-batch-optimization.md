# 正式 GPU：二进制几何、稳定描边缓存与批次效率

日期：2026-09-24。接续 Brandenburg 全量验收，落实此前对 luma.gl、deck.gl 和
`deck.gl-geoarrow` 的源码研究。保留现有 luma 后端与可编辑 topology dataset；未安装 deck/GeoArrow，
未把源数据再整体转换成一份 Arrow，也未升级生产依赖。

## 借鉴与实际实现

实现借鉴二进制属性、数据变化与视图变化分离、稳定批次追加机制；实际性能由下方同数据对照记录。
外部依据：[deck 性能指南](https://deck.gl/docs/developer-guide/performance)、
[GeoArrow Polygon 实现](https://github.com/geoarrow/deck.gl-geoarrow/blob/b3b93c3821d26a386a5ed44f74ec184ad1d14b0d/packages/deck.gl-geoarrow/src/layers/solid-polygon-layer.ts)。

### 平坦几何处理

`flat-polygon.ts` 直接处理 Float64 XY、环 offsets；保留原有 even-odd 父子环算法、任意绕向、
孔洞、嵌套岛和原有 Earcut 索引语义。单环省去空间包含树；相邻环直接引用连续数组，只有真正
非连续的 shell/hole 组合才重排相应坐标。高低位 GPU 坐标不改成单精度源坐标。

`flat-path.ts` 直接生成点、路径和正式仿射屏幕路径缓冲，不再先恢复整套 Point[][] 再拆成数值数组。
线段邻居、闭合标记、累计虚线距离、范围裁剪元数据与旧实现有逐数组等价测试。
特殊投影/过滤策略保留原参考处理，箭头仍使用原有的方向路径处理。

对超过 128 个要素的批次，最多 16 个点的简单单环直接将索引加入批次，最后统一打包坐标，
避免为数百万建筑创建独立 mesh 并反复挤占要素缓存。复杂几何继续使用完整的精确要素缓存。
GPU 索引拆包/视口压紧也改为 TypedArray 重映射，而非逐顶点 Map 和 boxed number[]。
保守上传覆盖外的完整要素在三角化之前剔除；包围视口的 shell 及其全部孔洞仍保留。

### 稳定描边精度档位

正式不透明实线的半像素过滤使用源范围中心作为固定锚点，八档/倍频的保守分辨率。
选中档位不低于请求的设备像素分辨率；同一覆盖和档位内平移不使坐标缓冲失效，
最终通过现有 AffineTransform / GPU screenView 重投影。数据、成员、DPR、档位或编辑版本改变仍正确更新。

这是显示近似：相对未经屏幕过滤的投影，坐标截断误差仍不超过每轴半设备像素（数值精度除外），
但采样网格的相位与旧版逐视图截断不同，默认描边因此可能存在像素差异。短线塌缩的 0.1 设备像素
端点补偿沿用原算法。`screenPathFiltering: false` 保留原始路径；半透明、虚线、箭头本来就不走此优化。
已增加两后端的原生平移回归：有覆盖、相同成员下无新增几何任务和上传。

### 计算批次与 GPU 分配分离

源空间分批的目标从 65,536 顶点/4,096 成员调整为 262,144 顶点/8,192 成员，
每个子块使用真实紧包围盒，以各子块的实际范围参与选择。单个有界任务的绝对顶点上限不变。
计算批次可以更大，GPU 仍按原有小缓冲限制拆分，未实现一个无限增长的全局 Buffer。
多彩图标保持原始有序页。描边共享弧去重使用请求私有位图，临时存储为原 Uint8Array 的约八分之一，
没有共享可变去重状态跨 await 导致竞态。

### 调度与刷新

请求有单调队列游标，不在每个小任务后扫描已完成前缀；工作集集合按选择变化缓存。
预算满足时直接返回；需要淘汰时才生成 LRU 候选，并在所有权变化前复用候选游标。
保留帧收集期驻留保护、精确成员比较、延迟结果版本检查和取消语义。

渐进刷新按实际提交成本合并（上限 250 ms），首批有反馈，最终完成立即通知。
没有新任务时不产生循环重绘。每次呈现仍清空后按图层/样式顺序重绘当前就绪内容，
每次清空后按顺序合成，alpha 每帧仅累加一次。导航即时几何重绘与后台进度刷新仍分开。

### 导入后的元数据注册

`TopologySource.setDataset(..., false)` 仅在不同的浅层包装、相同 layers/arcs 和相同记录的几何版本下
复用现有 DisplayArcs。显式替换、原地版本变化、不同几何或重投影仍重建；不重新恢复一遍相同的低细节弧。
GeoPackage 的 SQLite、WKB、共享拓扑及巨型结构化克隆本轮没有重写，仍可能存在多秒主线程恢复。

## 预算与范围

维持 256 MiB 几何软预算、512 MiB 工作集保护、64 MiB/20,000 条 Worker 要素缓存。
依旧一个按需启动的几何 Worker；这轮先消除串行链路重复工作，没有未经对照就默认启用多 Worker。
未接入全局 GPU 分页分配器、WebGPU RenderBundle 或第三方完整 Arrow renderer。
这些是待实施和验证的可选路线。

## 验证方法

先保存改动前工作区，再在同机独立 Chrome 顺序测试 before-webgl2 / before-webgpu；
pass1 仅含平坦处理和调度；after 包含稳定档位、计算批次及 LOD 注册复用。
输入仍为 1,048,797,184 字节、20 表、5,028,831 要素的 Brandenburg 原文件。
逐表 COUNT、源 SHA-256、默认 topology、Point LOD、DisplayArcs 和内存限制均核验。
未清空文件系统缓存；结果是本轮测量，非跨机器或多次中位数。

改前每后端一轮真实手势，改后每后端三轮；都包含固定 4/16/32/1 倍视图。完整更新需确认
pending 清零、导航结束、渲染队列清空及请求真实驻留。等待包含约 0.5 秒的静默确认。
首批/完整帧记录的是浏览器提交，非端到端呈现时间；RSS 为进程组采样合计，JS/GPU 数值分别列出。
GC 仅用于测试末尾释放验证，不影响计时。

原始日志和截图：`test-results/optimization-round/`，未上传原始用户文件。
