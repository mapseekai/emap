## 渐进出图与导航能力

正式 WebGL2/WebGPU 按就绪顺序准备资源、按图层顺序渐进显示，并在手势期间持续补齐矢量内容。小图层仍使用同步几何准备，Canvas2D 保留已有自适应快照策略。公开图层、
样式、数据集、拾取、编辑历史不新增平行实现，原有 examples 自动使用正式渲染层。

### 有序渐进场景

面图层现通过组合 polygon command 管理填充与可选描边；二者不再独立发布半成品。
同步单位依据实际面块、共享弧段和旧/新 LOD 的依赖形成，无关区域仍可渐进显示。
完整机制和边界见 [面与边界同步显示](luma-polygon-presentation.md)。下述原有通用
渐进策略继续适用于独立点、线及无描边填充；历史验收数字对应各自记录的实现阶段。

每次绘制先记录父图层/表达式桶的有序命令，然后清空当前 render pass，按原顺序重绘已经
就绪的几何。后续任务就绪会合并通知，再清空并重绘，使 alpha 每帧仅累加一次。
首个局部帧显示已就绪部分，完整场景随剩余任务完成逐步补齐。

分块准备在图层/通道间轮转；首次优先准备可用点/路径，避免复杂面三角化独占首次反馈。
CPU 分块/选择按时间片让出，而非每固定少量记录强制等待定时器。Worker 一次仍只接收一个
有界任务；取消结果、移除源和编辑版本继续隔离。

同一版本、样式和成员集合的旧屏幕 mesh 可以作为正在替换块的临时几何。每块只选择
当前版本或兼容旧版本之一；过滤、属性、几何或样式变化时丢弃失效旧内容。

### 超大面内部的三角形裁剪

Worker 将同一均匀 paint 内的完整三角形按空间顺序组织，再为连续索引范围建立保守 XY
包围盒。索引范围以完整三角形为单位；所有原始三角形和孔洞保留，没有裁切或改写源环。

主线程为范围建立 Flatbush，在每次相机变化时选择可见索引区间；GPU 只提交选中的 index
ranges，不重新三角化、不改写或上传坐标缓冲。包围整个视口的三角形仍保留。范围太零碎时
宁可提交保守的全部三角形，也不丢弃几何或发出无界 draw calls。

已核对当前 luma 依赖的索引偏移语义：WebGPU 使用 firstIndex（元素），当前 WebGL 实现
通过 firstVertex 传入索引字节偏移。适配封装在 GpuRenderer，业务层不依赖该差异。

### 冷块内部的精确要素复用

几何 Worker 增加以 source、原始几何身份、feature ID 为键的缓存，逐项验证 XY 和环偏移。
边界块因过滤或视口成员变化需要重建时，未改变的面可复用完整三角化结果，而不只复用
整块 mesh。源坐标或孔洞改变时重新生成。结果打包会复制为自有 GPU 数据，转移结果不会
detach 缓存的三角形；视图退远形成的空面不挤占有用缓存。

缓存按 64 MiB / 20,000 条的双重上限 LRU 管理，源移除和 Worker 销毁释放；它是另外的
Worker 资源，不属于 256 MiB GPU 几何软预算。Worker 被取消重建时诊断计数可能重置。

### 手势期间的新区域与文字

正式 GPU 导航立即复用原缓冲按新 AffineTransform 绘制。路径范围和三角形范围随相机
重新选择，点、图标和文字保留 CSS 尺寸。
既有屏幕描边依据其生成视图做仿射重投影，新的精细屏幕缓存就绪后替换。

每约 80 ms 合并一次最新视口的规划与文字布局请求；在手势中仍可复制/计算一个有界块并
呈现新覆盖。Worker 进度通知默认约 32 ms 合并，交互时约 80 ms。实际帧率取决于浏览器
调度和计算量。结束手势总会校准最终视图。仅相机变化且原始成员仍相同的有界任务允许完成作为
临时几何，避免在慢设备上被每次视图更新反复取消；版本、内容或需求改变仍立即取消。

已有注记使用原始地面锚点加 CSS 偏移重投影，字形/halo 不随地图倍率拉伸。旧标签继续
参与当前屏幕碰撞，异步布局发现新候选；同内容的进行中布局不被每个 pointermove 无限
取消。atlas 页发生回收时，代际检查防止旧 UV 误采样成其他字形；受回收影响的旧注记可
暂时隐藏，新的有效布局会替换。字体和每视图注记容量限制没有提高。

## 资源与失败语义

小几何与分块共享 256 MiB 软预算、512 MiB 工作集分配保护。当前 replay 使用的 mesh
受保护，不会在帧后被软预算清掉而造成下次导航缺图。新 GPU 分配前检查共享工作集，
超过硬界限明确报错，不暗中截取源要素。空间索引、Worker 64 MiB 要素缓存、输入包、
源数据、字体和其他纹理各有自己的存储，不把此几何预算描述为浏览器总内存。

画面提交失败会使 replay 失效；地图释放清除命令引用、索引、mesh、Worker、进度/导航
定时器和字形资源。Worker 失败不静默切回巨型主线程同步三角化。

## 加载阶段与性能适用范围

基准先完成原始文件解析、CRS 标准化和业务索引，再测正式渲染阶段的首次渐进出图。
首个 Worker 任务需要计算时间，单个复杂面在形成合法三角化后提交。
已缓存的三角网裁剪减少后续 GPU 实际绘制，初次计算单独完成。

主动导航补图比纯快照更实时，也会增加 GPU 绘制和有界 Worker 工作。旧阶段“手势零 GPU
重绘/上传”与当前策略分别记录性能。响应时间需按目标数据和设备测量；超大文件与极端单要素
使用真实文件验收。Brandenburg 的专项结果见本文开头链接。

## 大文件缓存压力下的补充保护

帧收集期间，点或覆盖物的即时缓冲可能先于后续面/线图层请求进入缓存。因此在所有绘制槽登记
完成前，仍保护上一帧的有效请求；全部图层登记后再判定可淘汰对象。完成判断还验证
条目实际驻留，丢失的条目清除 ready 标记并重新入队。

冷近景的面三角网在 Worker 中按扩张视口筛选完整三角形范围，压紧只包含所需顶点的上传缓冲。
覆盖边界按源空间二进制网格对齐，预取约为视口跨度的 1/64，外加网格对齐余量；绘制阶段仍按
真实视口做细范围裁剪。保守范围覆盖与视口相交或包围视口的面，也可能包含屏幕外三角形。
如果同精度完整缓冲已经驻留，则直接复用，不因缩小视野重复上传。覆盖键与精度、原始成员共同
参与缓存失效；原始几何、属性及完整要素三角化缓存不变，未提高 256/512 MiB 的几何预算。
