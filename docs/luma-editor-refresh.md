# LUCC 顶点反馈与加载闪烁修复

范围：本地 luma集成 分支的独立 luma-vertex-editing 示例。默认 emap viewer/editor 不变。
原始 mapshaper dataset、共享拓扑、源 CRS、原始选择和编辑命令保留。既有点聚合、描边屏幕过滤保持独立。

## 问题与复现

完整使用 /Users/zhang/Desktop/测试数据/lucc.geojson，9,384 个要素、3,932,506 个拓扑顶点。
基线在第 0 行及包含 4,664 个环的第 8394 行进行真实指针拖动。第 8394 行的受影响面块
单次重建约 2.846 秒，旧实现会提前清空全部屏幕描边与受影响原始缓存，期间出现缺块和
原始/过滤描边切换。较大拖动还可能改变洞的归属，不能只修改坐标而保留失效的三角连接。
首次普通加载未在基线采样中捕获缺块帧；加载期间 resize/重绘会穿过未完成的准备流程，
本轮增加明确的首帧门控，并用加载中 resize 的浏览器回归覆盖此路径。

## 实现

1. 原始三角网有界复用：Worker 缓存上限 128 MiB。未变更的 shell/hole 分组直接复用；
   局部坐标变化要检查三角形方向和与其他三角形的正面积重叠。结构变更、退化、不确定条件
   或检测超预算均重新三角化。环包含关系仍使用相同奇偶判定，长环通过边索引过滤候选。
2. 编辑缓存按版本原子替换：保留旧的完整填充和描边，后台准备所有新资源，完成后同步切换。
   同一视图只重建受影响的屏幕描边块，未变更的资源不会被清空或重复上传。
3. 背景和编辑覆盖层分离：背景快照不含选中轮廓、白色手柄或红色预览；这些都每帧以原始
   坐标通过 luma 重新绘制。底图需要重建时可暂时保留旧完整底图，但手柄的新位置无需等待。
   位图捕获显式使用 unpremultiplied alpha，防止 WebGL 背景半透明填充二次乘 alpha 变暗。
4. 加载门控：加载/恢复阶段不提交部分几何帧，resize 与异步回调只能更新最终视图。旧任务
   无权覆盖新加载的数据。清理时释放旧位图、GPU 纹理、三角网缓存及 Worker。

## 测量口径

使用真实 LUCC 完整文件，不用规则生成数据做性能依据。小型单元几何仅验证缓存有效性、
闭合环、洞、坐标版本和资源生命周期。性能与功能测试覆盖普通要素、复杂要素的放大局部编辑、
以及复杂要素的全范围大移动。第三种会改变洞结构，仍必须进行完整重建；不能宣称所有编辑的
背景同步都是即时的。手柄提交时间和后台填充就绪时间分开记录，不把提交耗时当 GPU 执行时间。
背景纹理已经 resolve 为 8-bit RGBA，再合成覆盖层有少量量化/边缘差异，不能宣称逐像素等价。
测试对直接绘制和背景复用图像做像素差约束，检测整幅变暗、残留手柄和透明度闪动。

## 当前实测（DPR 1）

Apple M4、16 GiB、Chrome 153 headless；浏览器窗口 1320×1000，编辑绘图区从实际 DOM 读取。

手柄提交从 mouseup 至示例下一次提交新版本覆盖层计时，不等同于屏幕发光或 GPU 执行时间。

## 最终验证

DPR 1 与 1.25 下 WebGL2/WebGPU 的 LUCC 专项全部通过；高 DPI 另跑 2 项，含新位置像素、
背景合成差异、加载中 resize、局部/大范围拖动、撤销和重做。大幅拖动或缓存有效性检查不通过
仍会完整三角化，不把后台耗时隐藏为即时完成。最终共 20 项针对性浏览器检查通过（8+6+4+2）。
