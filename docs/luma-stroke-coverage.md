# 描边范围裁剪与同色填充物理合批

本轮继续优化正式 WebGL2/WebGPU 的已驻留场景，不修改 GeoPackage 导入、源拓扑、显示 LOD、
字体、线宽、MSAA、GPU 预算或 Worker 并发数。基线为本轮开始时完整的未提交工作区，
不是远程 master 的旧代码。原始日志位于 `test-results/render-envelope-round/`。

## 实现

`stroke-ranges.ts` 为不透明、已进行屏幕过滤的描边增加保守的连续实例范围。
紧凑描边保留每条 48/64 字节记录及其原有顺序；长描边继续使用原共享邻接缓冲，不复制成另一种 GPU 格式。
每个范围的边界包括端点，查询余量覆盖整个六顶点线段/端帽/连接包络，另加像素边界余量。
尖锐或近反向连接不能证明包络足够小时，整个范围始终保留，宁可多画而不漏画。

范围索引驻留在 CPU；导航将当前视图转换到生成这份屏幕几何时的坐标基准，选择已有缓冲的实例区间，
不重新上传、不裁切原数据。普通源坐标路径维持原来的空间选择。范围元数据、Flatbush 存储和例外索引
计入几何缓存预算，随所属条目释放。相同视图复用范围选择；同一 paint/basis 只计算一次查询视口。

`MeshCommandCache` 对同一常量 RGBA 面填充绘制作用域按物理缓冲和索引偏移组织批次。
即使 alpha 小于 1，每个样本上相同颜色/透明度的 source-over 操作次数仍保留；不跨不同颜色、父图层、
纹理或文字命令。只合并相邻且实际被选择的区间，不跨越过滤或回收的洞。半透明描边不因此获得重排许可。

`pathFrameCandidates` 与 `pathFrameSubmitted` 分别记录当前调用中候选与实际提交的路径实例，
包含原共享邻接格式的无效/分隔记录，不应解读成源要素数。WebGPU 命令复用继续计入内部的逻辑绘制工作。

## 未采用的试验

严格共线的屏幕中间点合并虽减少约36万显示点，但改变了既有连接/光栅化边缘；Brandenburg对照出现
数千个像素差异，专门的转折/回退测试也不通过，因此已撤回，未作为默认优化保留。
紧凑线段的 Morton 重排在本轮 WebGPU 全图测试中退步，也已撤回。最终版本保留线段原始绘制记录顺序。
两项试验的日志保留在 `coalesced-*`、`spatial-*`，不能混入最终实现的跑分或通过数。

## 续接验收

范围与同色面工作连同可见区间合批已经完成续接验收；实际收益有限，不能把少画的实例或少量draw当作整体GPU提速。
最终同场景对照、非等比回退及验证边界见 [可见区间合批](luma-selected-range-batching.md)。
