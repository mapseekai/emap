# 已驻留描边裁剪与可见区间合批

本轮续接此前未收尾的描边包络范围工作，并补齐裁剪后的共享页合批。
复用已有 Buffer 的可见实例区间，保留文件导入、原始拓扑、显示 LOD、坐标精度、MSAA、线宽、字体与 GPU 预算。
未提交工作区是测试基线，不以远程 master 的旧实现替代当前基线。

## 实现与正确性

1. 描边范围索引保留原有实例顺序，以端点、连接和端帽包络保守筛选连续实例。
   尖角包络安全性尚未确认时保留整段；原共享邻接长路径不转换成膨胀的 GPU 布局。
   范围、Flatbush 及例外记录的存储计入几何缓存。导航只选择已有 Buffer 的区间。
2. 同一常量 RGBA 的面填充作用域按物理页组织，保留每个样本上相同颜色 source-over 的次数。
   不跨父图层或不同 paint，不扩展到半透明描边、图标、纹理与文字。
3. 同页相邻逻辑块即使只部分可见，也能生成一个共享绘制计划。合并相邻可见区间，
   不跨未选择区域、过滤洞或已回收 slice。部分填充计划不绘制对齐 padding。
   完整可见计划仍沿用原有退化三角形 padding 和真实三角形统计。
4. 每个范围先在原始 mesh 的局部空间验证，再扩大共享 span；每个范围按原始 mesh 边界校验。
   所有原始成员继续登记资源依赖。WebGL 范围 VAO 归属第一个真实 mesh 的有界缓存，
   不遗留仅由临时 span 持有的 VAO。
5. 屏幕描边包络只在正向等比变换兼容时复用。非等比相机下保留原始绘制，
   不拿旧连接角的包络裁剪新连接。新增真实后端回归先复现该条件，再验证安全回退。

## 测量口径

Brandenburg 全量 20 表、5,028,831 要素；同机 Chrome、1280×852 CSS px、DPR=1、4×MSAA。
CPU 提交 12 个暖帧样本和硬件 GPU timestamp 12 个样本分开采集；两者按各自统计口径分别解读，FPS 需另行采样。
本轮 `test-results/render-range-batch-round/before-*` 是续接时的实现，`after-*` 是增加成本保护前的区间合批阶段；
前段 `test-results/render-envelope-round/before-*` 仅用于标明此前范围工作，不混同为本轮纯合批基线。

## 同场景对照与提交成本保护

独立前后运行的页分配历史可能不同，draw 数变化需结合页分配历史分析。
因此增加同一驻留场景的 A/B/B/A 对照：保持相机、几何 Buffer、可见范围和样式相同，
仅替换旧/新可见范围编译策略。每一模式先暖机三帧，再记录 CPU 与 GPU 样本。
原生 WebGPU 命令复用在两种策略下都保留，不拿未录制路径与已录制路径冒充范围合批收益。

初次对照发现：若一个部分可见面混入多段完整填充，排除 padding 可能拆开此前更便宜的完整 span，
反而增加 draw。最终编译器比较区间数；更贵时保留旧完整 span 方案，不跨过未选择区域来凑合批。
对应失败复现和属性测试覆盖了随机碎片、重复区间、多种 padding、遗漏 slice 和越界范围。

`after-*`、`ab-*` 为成本保护前的中间数据；最终验收使用 `final-ab-*` 和 `stress-*`。
`final-ab-*` 中一轮导航后的固定视图仍保留原文件完整性及释放检查，A/B 计时不含录制暖机、
源导入或文件读取。GPU 时间与 CPU 时间分别记录，不把较少的命令对象等同于 GPU 提速。

## 最终同驻留场景 A/B/B/A 结果

每个策略两组各6次 CPU、6次 GPU 样本，合并12个样本取中位数。相机、GPU Buffer、可见实例及三角形数量逐项相等。
两种策略保留同样的 WebGPU RenderBundle；每组前3帧暖机不计时。此诊断每次CPU提交后等待GPU空闲，
与此前连续RAF提交的绝对CPU时间口径不同，与以前报告按各自采样口径分别列出。

| webgl2 全图 | 11.20 → 11.45 | 23.62 → 23.28 | 739 → 739 |
| webgl2 4× | 21.40 → 22.80 | 35.87 → 35.58 | 2095 → 2094 |
| webgl2 16× | 7.95 → 7.75 | 17.26 → 17.59 | 537 → 528 |

结果没有显示明显的整体提速：部分近景少了4–9次绘制，完整范围几乎没有这类可合并的部分区间。
GPU执行时间基本相近，部分CPU样本更慢；不把独立运行中的页分配差异或计时波动当作该规则的加速。
保留的改动明确改善了区间组织和安全边界，但没有解决长路径/复杂连接的实际GPU工作量。
