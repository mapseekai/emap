# 点数据自动 LOD：设计与实施计划

日期：2026-09-10。实施分支：`feat/point-lod`；基线：`55f2fa2e`（0.10.1）。

## 目标与边界

低比例尺下，从屏幕上密集重叠的点中保留真实代表点；放大后逐步恢复更多点。
不移动坐标、不删除要素、不生成聚合气泡，不改写属性、导出数据或分析结果。
沿用 Canvas2D 和现有 Flatbush；不引入新依赖，不重构线/面 LOD。
本次是密度抽稀，而不是所有符号之间严格无碰撞的标注布局系统。

## 现状与接入位置

`FeatureQuery.getRenderCandidates` 已提供点/线/面的视口候选，`null` 表示全量扫描，空数组表示无候选。
线/面另有 `DisplayArcs` 和像素尺度简化；点目前只有候选裁剪与 Canvas 的 100 点批次绘制。
在图层渲染编排中增加 `PointLod`，CanvasPainter 仍只负责绘制传入的点。
点绘制路径：显示过滤 → 尺度代表点选择 → 视口裁剪 → 保留原始样式分桶 → Canvas。
未启用 LOD 时保留现有候选裁剪路径。

## 核心算法与缓存

使用锚定数据坐标原点的网格，按 AffineTransform 将 CSS 像素单元大小转换成地图单位。
尺度量化采用二进制嵌套网格；平移不改变分格，缩放切换尺度，不跟随屏幕左上角移动网格。
代表点采用确定性的要素 ID/分量 ID 排序或稳定哈希，保留原始坐标与属性；输出维持确定的绘制顺序。
网格单元大小不能宣传为严格最小点间距；相邻单元的点仍可能重叠。
缓存有限数量的尺度结果；平移只查询已抽稀的结果，不重新扫描百万个原始点。
首次尺度构建成本、暖缓存查询成本分开测试；高比例尺稀疏场景需避免不断重复构建无收益缓存。

## 正确性约束

- 显示过滤必须先于代表点选择，过滤掉原代表点后应选出同单元内仍满足条件的点。
- 缓存需覆盖 dataset/shapes 身份、要素数量、editVersion、attributeVersion、过滤条件、CRS 与图层配置。
- 同源的不同渲染图层不能互相污染缓存；移除图层、数据源、地图时释放缓存。
- 支持 Point 与 MultiPoint；必要时通过原始 feature ID + component ID 的紧凑数组扩展绘制接口。
- 不复制 GeoJSON，不产生随机结果，不在逐帧热循环创建大量字符串网格键。
- 坐标使用双精度；正确处理负坐标、任意平面 CRS、无效坐标、空数据、视口边缘与 DPR。
- 样式以原始 feature ID 解析，不在各样式桶中分别抽稀导致显示量失控。
- 选中、高亮、编辑对象使用现有独立叠加绘制通道，不被普通点 LOD 隐藏。
- 指针拾取应优先实际绘制的代表点，并包含选中/高亮叠加点；不能把渲染抽稀写进业务过滤掩码。
- 框选、套索、属性表、分析、统计与导出保留原始数据语义；指针与范围查询的差异必须说明并测试。

## 对外配置

大数据点图层默认自动开启；小数据与无收益情形保留原路径。
提供每个 circle 图层的 `pointLod: false`，允许用户查看所有原始点。
必要的高级配置只暴露像素单元大小等少量、可序列化的参数；不加入未实现的 cluster/WebGPU 模式。
新增参数在 addLayer 处验证，嵌套配置独立克隆，支持图层配置 JSON 往返。
`.msx` 仍为源数据快照，不新增渲染配置协议；验证抽稀后原始数据无损往返。
不重构统一 Geometry LOD；这次只补齐点数据缺少的降量路径。

## 独立审查补充（实现期间）

已验证原有 6 个相关测试文件、125 项测试通过。
初版独立压力测试发现：固定 100000 个代表点上限会让普通 1920×1080 视口在尺度临界处突然退化。
复现：固定种子 12345 的 1000000 个均匀点，范围 [0,0,960,540]，cellSize 默认 8。
当 |mx|=|my|=2 时保留 32400 点；尺度变为 2.001 后，初版返回 null，重新画全部 1000000 点。
这只是轻微放大，不应触发全量绘制；4K 视口的风险更大。必须补充回归并修正预算策略。
缓存预算不能通过在普通高密度场景完全关闭抽稀来实现。应覆盖完整视口所需单元，或采用局部分块/分层回退。
同时检查极小 cell 下有限大坐标除法溢出或超安全整数范围，不能把不同坐标误合并成 Infinity 单元。
当前 .msx 快照仅保存源数据，不保存渲染图层配置：本次不要扩展整个快照协议；验证原始数据无损即可。


## 实际实现（2026-09-10）

- `src/renderer/point-lod.ts`：按 feature ID / component ID 升序首次占格，双精度坐标，有限且安全整数的格坐标检查。无效点跳过，无法安全分格时回到原路径。
- 默认 `cellSize=8`，合法范围 `[1,64]` CSS 像素，`false` 关闭。至少 10000 个有效过滤后分量且降量超过 10% 才使用 LOD。
- 预算为完整 CSS 视口按半 cellSize 分格后的单元数的两倍，且不超过 `64 MiB / 80` 个代表点。后者是构建内存规划额度，不是 JS 堆用量保证。最多三个 LRU 尺度索引；还保留当前已绘制尺度供 CSS 快照导航拾取。
- 超预算会尝试更粗的二进制尺度，而不是返回全量绘制。已知预算下限复用于更细尺度；单点图层完整视口的原始空间索引候选足够少时允许原路径恢复局部细节；MultiPoint 不把要素数误当成坐标分量数来启用这个回退。查询矩形不参与预算。首次超预算构建可能进行多轮扫描，暖平移不扫描原始点。
- 代表点 Flatbush 查询后输出原始 ID；同矩形复用结果对象，全范围复用尺度级有序数组。绘制接口增加与 feature ID 平行的 component ID 数组，按样式桶单次遍历代表点，复杂度 `O(M+B)`。
- 指针独立使用已绘制尺度与裁剪范围，快速 CSS 缩放不会提前切换到尚未绘制的新尺度；选中/高亮分量使用原始覆盖通道。范围查询和业务过滤掩码不写入 LOD 结果。
- 生命周期按渲染图层、源和地图释放；新显式图层替代的默认图层缓存也会清理。数据/图层/shapes 身份、数量、版本、过滤掩码、CRS、cellSize、视口预算参与失效。
- `.msx` 协议无改动。回归通过真实 GeoJSON / MSX 导出以及真实 FeatureTranslateCommand 的 do/undo/redo 验证数据和编辑语义。
