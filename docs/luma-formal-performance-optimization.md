# 正式地图 GPU 导航与弧段准备优化

> 本文保留第一轮缓存/快照的历史测量。当前 GPU 导航使用驻留几何重绘与手势补图，见 [渐进渲染](luma-progressive-rendering.md)；本页零重绘数字对应旧快照策略。

日期：2026-09-23。基线 `17fd94c2`，工作分支 `master`。
本轮实现前次 [性能检查](luma-formal-performance-audit.md) 的第一优先级，并补齐近景候选边界准备。
本报告记录该阶段本地修改与本机验收；当时尚未推送或发布。

## 导航预览与弧段缓存能力

1. 正式 GPU 地图在有效完整帧上直接使用导航预览，不再要求上一帧 CPU 提交超过 33.3 ms。
   手势结束请求一次完整绘制；Canvas2D/未知后端的自定义 Painter 仍用原来的自适应策略。
   内容变化仍完整刷新、更新相机基准；尺寸/DPR 改变或完整绘制异常后，旧快照不再有效。
2. Viewport 生成的弧段谓词带有内部可验证的语义键，记录原有长度阈值和边界；任意外部闭包
   不被信任为纯函数。没有改变过滤算法、原始数据、线宽或点 LOD 密度。
3. PainterGeometryCache 增加准备条件/实际几何两级检查。同一准备条件跳过弧段过滤；视口变更
   后若有序选择相同仍复用原 mesh。缓存副本检测 ID 原地变更，键包含源/图层/几何版本及保留级别。
4. 正式图层可将候选边界交给 GPU Painter 惰性展平，避免主图层循环先遍历再命中缓存。
   普通边界保持历史上的正向 arc，样式桶保留 signed arc，方向性箭头/虚线不会因此反向。
   旧 Canvas 和自定义 Painter 不实现可选方法时继续使用原收集逻辑。
5. 准备副本计入既有 256 MiB 预算，与 mesh 同 owner 同时淘汰/释放；未提高内存预算。
   冷路径使用紧凑 Int32Array，不增加临时 JavaScript 数字列表。

连续手势也保留上一成功绘制帧的变换基准：前一手势结束的刷新尚未执行、后一手势已经开始时，
不把新的相机位置误当成旧像素的基准，避免快照跳回。该时序有失败复现及独立浏览器像素回归。

## 实测口径

沿用原检查的完整 points.geojson、building.geojson、lucc.geojson、同一台 Mac/Chrome headless，
分别运行 WebGL2 和 WebGPU，地图 960 × 640 CSS px、DPR=1。
先在 benchmark 导入，再将同一数据交给正式地图，统一基础样式和 mx/my/bx/by；
每个稳定视图 6 帧。时间记录主线程绘制/提交中位数；磁盘冷读、首次解析/几何构建和 FPS 分别测量。
基线与修改后按 backend + filename + zoom 匹配，不依赖结果列表顺序。
另执行同样的 20 次真实鼠标移动，分别统计手势中与结束后的提交。

## 实测结果

单位 ms，稳定帧 CPU 绘制/提交中位数：

| 数据与视图 | WebGL2 优化前 | WebGL2 优化后 | WebGPU 优化前 | WebGPU 优化后 |
| --- | ---: | ---: | ---: | ---: |
| building.geojson，完整范围 | 10.55 | 0.60 | 10.40 | 0.50 |
| building.geojson，16× 近景 | 1.00 | 0.35 | 1.10 | 0.45 |
| lucc.geojson，完整范围 | 11.05 | 0.55 | 11.05 | 0.50 |
| lucc.geojson，16× 近景 | 8.45 | 0.40 | 8.90 | 0.45 |

同一段 20 次鼠标移动，WebGL2/WebGPU 均得到以下次数：

| 数据 | 优化前手势中重绘 | 优化后手势中重绘 | 优化前手势中上传 | 优化后手势中上传 | 优化后结束重绘 |
| --- | ---: | ---: | ---: | ---: | ---: |
| points.geojson | 20 | 0 | 20 | 0 | 1 |
| building.geojson | 20 | 0 | 40 | 0 | 1 |
| lucc.geojson | 20 | 0 | 20 | 0 | 1 |

六组文件/后端的正式点、路径、填充提交计数与优化前逐项一致，稳定帧均没有新增几何上传。
这是消除主线程重复准备与手势重复提交，点数、化简阈值、颜色和透明度均保留。
本轮新增准备副本在 building 完整范围约 1.04 MiB、LUCC 约 0.79 MiB，计入原有缓存预算；
浏览器总内存需另行采集。全部六组无 pageerror/地图错误，释放后 Worker 数为 0。


## 验收与边界

调度器、两级缓存、纯谓词、候选边界和 Painter 有专门回归，覆盖原地数组变更、版本/保留级别
变化、状态闭包、显隐/移除、异常和缓存预算。浏览器读取真实 compositor 截图验证导航画面，
不会为取样强行调用 render 来掩盖快照错误；手势中修改样式/过滤/源也验证立即更新。
既有真实顶点拖动、撤销/重做、MSDF、icon、栅格组合及生命周期回归继续执行。

本轮没有迁入完整的空间分块/几何 Worker 或屏幕描边缓存。首次大几何构建和新可见集合的冷更新
仍可能较慢，GPU 提交几何总量保持。稳定 CPU 时间的改善来自本轮准备缓存；完整管线与
benchmark 的对齐及各场景 FPS 需要后续测量。后续工作保留在本地迁移报告中，
未创建外部问题或发布代码。

原始数据未改写或上传。性能 JSON、诊断脚本副本在 `test-results/formal-luma-navigation-cache/`。
