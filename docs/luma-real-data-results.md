# luma 集成：五份真实数据验证

日期：2026-09-19。分支：`luma集成`。本次仅使用用户明确授权的五份本地 GeoJSON。
原始文件未复制进仓库、未修改、未上传。性能报告不使用规则生成数据。

## 范围与测量条件

本阶段通过独立 `luma-benchmark` 示例比较同一显示策略的 Canvas 与 luma 绘制。Apple M4、
10 logical cores、Chrome 153 headless、CSS viewport 1238×450、DPR 1.25。
A/B 顺序为 Canvas → luma → luma → Canvas，每轮预热 12 帧、采样 30 帧，
每后端每视距合计 60 帧；两者使用同一份原生 dataset、相同 LOD/可见分块/样式/轨迹。
帧率来自 rAF 间隔；CPU 是 JS 绘制/提交。本轮 GPU timer 未测量。
远景倍率 `exp(-3.2)`；近景为完整范围视图的 16 倍，按该视图的可见块与 LOD 提交几何。

## LUCC 问题复现

旧全量 GPU 原型使用同一文件：9,384 要素、3,932,506 个拓扑顶点，
GPU geometry 271,310,376 bytes。在远景静态重绘的 12 次记录中，JS 提交多为
1–2 ms，但多个 rAF 间隔达到约 1.2–1.3 秒。GPU 帧耗时需独立测量。
新版同尺度静态重绘约 16.66 ms/帧；独立暖 A/B 远景也约 60 FPS。
旧、新静态样本和新 A/B 轨迹分开保存，不将不同测量口径混算成精确加速倍率。

## 显示策略与资源管理

源 dataset 的坐标、属性、CRS 和版本不被显示 LOD 改写。共享弧使用独立简化阈值；
点网格保留真实原始点代表，亚像素短边允许不描线，闭合环保留最低非退化表示。
渲染缓存以 192 MiB 估算预算淘汰非活跃细节，保留粗级后备；这约束的是显示资源，
浏览器进程内存还包括源数据与其他资源。导入后数据仍需驻留，Worker 持有渲染副本。

空间分块先按源坐标分桶，再限制每块要素/原始顶点成本；视口按块包围盒查询，
不会因为边界在屏幕外而误删包围视口的面。不同 LOD 不叠加绘制同一个半透明块。
细节请求可取消并按源代次校验；拖动/滚轮时不继续新建细节，停止后补齐。

本轮验证完整显示策略的效果。远景点或线场景中，LOD 后 Canvas 的 CPU 开销也可能更低；
两者已经约 60 FPS 时，继续比较 CPU 成本、加载和响应时间。复杂自交面、编辑过程、
全量属性样式及其他浏览器需按目标场景补充验证。

## 复现

```bash
pnpm examples:build
pnpm benchmark:luma:real --data-dir /Users/zhang/Desktop/测试数据 --frames 30
```

脚本只接受五个授权文件名，启动独立 4193 预览，结束后关闭自己的服务；不操作用户的 4187 服务。
为避免机器负载干扰，运行时保持前台机器空闲，不要同时构建或运行其他性能测试。

手动入口：`/mapseekai/emap/examples/luma-benchmark/`。选择本地文件、在下拉框选择
待加载文件、点击“加载文件”；等待就绪后切换后端、拖动/滚轮或点击 A/B。
首次加载会准备缓存；测试页没有伪装 Canvas 回退为 luma。

## 本轮最终验证

相关单元/回归：18 个测试文件、228 项通过。实际浏览器回归：5 项通过，包含真实 big 流式导入取消、真实 points 再加载、真实 LUCC 的 LOD、暖导航零上传与资源释放。
类型、示例类型、公共类型契约、架构、测试布局、生产构建和 `docs:verify` 均通过。五份数据各三个视距的完整性能结果另见上述报告，不用规则生成数据作为性能结论。

GPU Buffer 按 byteLength 分配后写入数据，避免 luma 初始化 props 保留大块 CPU 上传数组；缓存不再额外保留已经上传的 vertex/index 数组。
用户 4187 预览服务保持原进程运行；自动化自己的 4193 服务在结束后已关闭。未提交、未推送、未发布。
