# 正式 GPU：绘制计划、MSAA 命令复用与空闲页区间

日期：2026-09-24。接续 `luma-stroke-rendering.md`。只优化已加载矢量的准备与绘制，
不改 GeoPackage 导入、不降低 MSAA、不删除源要素，也不提高几何工作集预算。

## 实现

### 可复用的有序绘制计划

`mesh-command-cache.ts` 将同一绘制作用域的 mesh、连续页区间和精确可见范围编译一次。
范围按值快照，mesh 身份及缓冲/偏移/数量逐项核对；相机 uniform 不属于几何命令身份。
相邻页 slice 的合并保持原顺序，合并遇到隐藏区间、不同画法或父图层边界即停止。
同一作用域内的不可变 paint 只解析一次，外部即时绘制仍逐次检查可变 paint。
WebGL2 和 WebGPU 都使用这层缓存，最多 128 个作用域、32,768 个命令/可见范围预算单位（细分范围计入预算）。
资源销毁时保守清空计划，未再使用的作用域在帧结束释放；没有缓存完整数据集副本。

### WebGPU 原生 MSAA bundle 桥接

`webgpu-mesh-bundle.ts` 只录制单 uniform 的面填充与不透明 MSAA 路径。
保持正式渲染的 sampleCount=4、depth24plus 和当前颜色格式；不修改 luma 依赖文件，
不替换原生 render-pass handle，不缓存整张位图，也不复制顶点缓冲。
使用 luma 的 VertexArray 绑定布局和 RenderPass.executeBundles 提交，正确重置适配器绘制状态。
相同有序命令出现至少两次且编译后不少于 8 项时才录制；少量或持续变化的命令走普通路径。
改变视口裁剪结果、样式、资源或偏移会重新准备。颜色/深度覆盖重置、scissor 留在外层 pass。
文字、图标、图像、虚线、半透明线和其他不满足条件的管线仍由原 luma 实时绘制。

当前安装的 luma v10 alpha 公开 bundle 构造器只接受 sampleCount=1，因此采用局部原生桥接，
多采样通过该适配路径接入。只补充开发期 `@webgpu/types@0.1.72` 类型依赖。
依据：[luma 接口约束](https://luma.gl/docs/api-reference/generated/core/type-aliases/RenderBundleEncoderProps)、
[WebGPU 命令与状态语义](https://gpuweb.github.io/gpuweb/)。

### 稳定帧免于反复扫描回收集合

只有上一帧全部任务已经完成、同一有序请求集合仍有效、资源世代和外部几何内存压力未变，
才跳过重复的图层归属、计划保留和淘汰维护。新任务、删除/替换资源、过滤、外部缓冲变化、
错误或不完整场景都继续执行完整维护，完成判断仍核实实际驻留，不仅检查旧 ready 标志。
`geometryChunks.maintenanceSkips` 记录跳过次数，不将其当作少画了图形。

### 空闲区间拆分和合并

回收的大槽位写入小块成功后，剩余容量重新进入空闲表；相邻区间只有顶点和索引两条地址流
都连续时才合并。上传失败还原完整空闲区，不提前提交拆分，也不会覆盖活跃 slice。
不移动存活数据，不重复上传整个场景，不增大 256/512 MiB 原有几何预算。
在线整理作用于空闲区间，活跃区间之间的空洞仍可能保留，回到全图的合批率取决于当前区间布局。

## 统计和测试方法

`renderCommands.recordings/replays/drawsReplayed` 分开报告录制、复用和复用的逻辑绘制次数。
原来的 `drawCalls` 仍累计实际逻辑 draw，executeBundles 次数单独统计。
计划采用有界存储；几何 Buffer 字节与驱动内部 bundle 内存分别计量，后者需通过驱动侧观测。

对照基线 `before-*` 与最终 `verified-*` 使用同一本地 Brandenburg 全量数据、一轮真实导航、
固定 4/16/32/1× 视图、DPR=1、MSAA=4。每视图 12 次 CPU 提交和 12 次 GPU timestamp 分开测量。
硬件队列异步等待只用于测量；连续手势 FPS 需另行采样。冷更新含约 0.5 秒的静默确认。
不并行跑其他压测，不清空文件系统缓存；报告同机本轮样本，不用历史版本跑分替代当前基线。
原始输入不修改、不上传。`after-*` 与 `final-*` 是中间阶段；最终 `verified-*` 包含有界范围计数和退役成员保护，不混用阶段跑分。

原始日志、截图与结果保存在 `test-results/render-command-round/`。

## 后续渲染优化方向

GPU 描边的像素覆盖、长线和复杂连接仍有计算成本；这次没有增加新的 shader 近似或降低采样。
当前空闲区间合并不搬动活跃数据，活跃 slice 隔开的碎片仍在，共享页布局和更完整的物理合批可以继续评估。

缓冲销毁时命令缓存保守整体失效，可以按资源依赖进一步细化；但必须防止回收页上的旧命令画出失效内容。
新视野、新精度的冷几何仍需构建，复杂面计算、Worker 有界并行没有在本轮改造，命令复用收益限于已准备的绘制命令。
文件导入继续留到最后，不以更改拓扑或属性恢复换取本轮渲染数据。

这些跟进记录在本地报告。本轮未获外部任务写入授权，不创建远程 issue。
