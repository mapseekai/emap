# 面与边界同步显示

## 对外行为

正式 WebGL2/WebGPU 的一个面图层，通过单个 `drawPolygon` 组合命令管理填充和可选边界。
现有样式字段不变：`fill-color` / `fill-opacity` 设置内部，`line-color` / `line-width`
设置边界，`line-width: 0` 禁用边界；`fill-opacity: 0` 保留仅描边的表现。
独立 `line` 图层不参与面的等待条件。Canvas2D 与仅实现原始 primitive 的自定义 painter
继续使用原先的同步调用路径，无需实现新接口。

GPU 底层分别复用 fill 与 path/arrow 几何和管线，以及现有源数据、三角化和描边算法。
组合命令统一管理 polygon 的所有权与可见提交时机，底层按各自管线提交绘制。

## 同步单位

填充按 feature 分块，描边按拓扑 arc 分块，区域对应关系通过依赖映射确定。
`polygon-groups.ts` 复用已有 partition membership，按真实 feature/ring/arc 关系建立依赖。
孔洞、反向弧段、共享边、路径合批、箭头描边及旧/新 LOD 分区都参与关联。

冷加载采用有向依赖：一个面只等待自己需要的描边，不要求共享边另一侧的面也完成。
Worker 为描边保留局部 arc 的 instance-range 元数据；部分帧仅提交已就绪面需要的边段，
多个面共用的边取并集、只绘制一次。该元数据随 compact/精确坐标分流和 GPU mesh 拆分
一起保留，计入原有几何缓存预算。坐标、三角化、描边 join/cap 算法及最终像素不变。
完整帧直接使用原批量绘制，不继续做成员掩码选择。

冷帧依赖规划复用已有源分区，并保留选中面所引用的 arc ID（以 ID 引用原坐标）。这些临时
紧凑 ID 列表设置 32 MiB 上限，超出时使用保守成组策略；旧/新资源切换的关联元数据
仍只与块数相关。

一个依赖组的所有目标资源就绪后才显示；未就绪时保留同内容版本的旧完整组，首次加载
没有旧结果时暂不显示该组。不同依赖组可分别推进，因此不会无条件等待整个地图完成。
旧大块覆盖多个新块、箭头描边或超出冷帧 ID 预算时，可能需要把多个块一起切换；
首次普通描边不再因共用一个 GPU mesh 就合并全部相邻面。保守替换场景仍可能形成较大等待组，
以保持当前 GPU 分块粒度下的完整性。首帧延迟随依赖组规模变化；图层始终按原绘制顺序提交。

每帧依然先按原表达式桶顺序画全部已选填充，再画该面的描边；不改成逐块交错画
fill/stroke，避免后面的面遮掉前面的边。每次清空并重组画面，不在旧半透明图像上叠加。
无描边、仅描边及小数据同步路径不增加这种依赖等待。完整暖帧直接复用已有资源，
不重复建立依赖图，不因组合绘制重新上传坐标。

## 生命周期

`PolygonPresentation` 只持有已有缓存条目及有序绘制函数；已显示的旧完整组继续通过
原有 GPU cache pin 机制保护，不提高既有几何预算。源/图层清除、过滤和样式内容变化
使旧内容持续失效；销毁与请求替换会取消依赖规划，过期结果不再触发地图刷新。
资源实际驻留与屏幕描边兼容性是成组检查，不允许只留下旧组的一半。

共享边同步最初采用无向整组依赖，会在这份 LUCC 上连成大等待组，因此未作为最终方案。
最终普通描边的冷加载使用有向成员选择；连续已选边段之间只跨越无效邻点填充记录合批，
绝不跨过未选中边。避免“一条源弧段一个 draw”的提交开销；半透明共享边仍只提交一次。
