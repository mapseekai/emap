WebGL 大数据渲染优化方向

目标是贴近 deck.gl / deck.gl-geoarrow：ArcCollection 仍是拓扑数据源，渲染侧建立 retained binary buffers，交互帧只做选择和 draw。

A

Worker 化整层转换

点、线、面都在 worker 里转换成 typed arrays；主线程只收结果并绘制。

优点

  • 改动最小
  • 能减少主线程长任务

问题

  • 仍然整层 clone 和 tessellate
  • 复杂面首屏仍慢
  • 不是 deck.gl 的核心性能模型
B

Retained Binary Chunk Pipeline

建立 source/layer 级二进制渲染快照，按 spatial chunk 转换和缓存；视口变化只选择 chunk draw。

优点

  • 贴近 deck.gl binary attributes
  • 首屏可渐进显示
  • 编辑可局部失效
  • 适合当前 ArcCollection 架构

代价

  • 需要新增缓存层和 chunk 生命周期
  • 测试面较大
C

Tile/Bin 渲染架构

把数据预切成 tile/bin，按 zoom/viewport 加载和绘制，类似 MVT/GeoArrow streaming。

优点

  • 性能上限最高
  • 适合千万级数据和远程流式加载

问题

  • 会改变数据加载模型
  • 和 Mapshaper 拓扑编辑集成成本最高
  • 不适合作为第一步

推荐

先做 B：Retained Binary Chunk Pipeline。它是对当前代码最稳的“deck.gl 化”升级：保留 ArcCollection 和编辑 API，同时把渲染侧改成二进制 chunk 缓存。后续 B 的 chunk 接口可以自然演进到 C 的 tile/bin。
