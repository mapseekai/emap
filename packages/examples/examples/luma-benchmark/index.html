测试口径与限制

这是独立 Painter 对照，不是默认地图引擎迁移。两种后端使用同一个 mapshaper dataset、相同视口/DPR、样式和轨迹；启用相同的保守空间裁剪，屏幕过滤关闭时绘制原始路径，开启时仅背景描边按 Canvas 屏幕规则过滤；点在开启聚合时使用同一组原始代表点，关闭后绘制全量点，手动交互可使用快照导航；A/B 绘制压测强制绕过快照。A/B 按 Canvas → luma → luma → Canvas 顺序单独运行，每轮预热 12 帧、采样 60 帧。拖动/滚轮可手动比较。

CPU 指标测量 JS 绘制/提交，不代表 GPU 执行完成；rAF FPS 受刷新率、后台标签页和机器负载限制。显存数字仅为已跟踪几何及图像的估算，不含驱动、帧缓冲、着色器等。栅格最多 64 个已解码 256×256 瓦片，导航不再读文件或切换 overview，因此不是 GeoTIFF 全流程测速。不再限制原始要素／顶点数量；本地矢量文件沿用 emap 的 2 GiB 导入上限。GeoJSON 在 Worker 中流式解析为原生 mapshaper dataset。点聚合只影响显示缓存，不修改原始坐标、属性、要素数量；未开启 Canvas 屏幕过滤时不因缩放省略短边；开启后可省略微小 arc 并对齐半设备像素，不改写源边界。仅剔除完整位于屏幕外（含符号扩张范围）的分块及连续路径范围；不改变屏幕内短边。缓存预算只淘汰屏幕外资源，可见工作集超预算时保留完整精度并显示占用，不回退为粗级几何。原始坐标、属性和 CRS 不修改。诊断绘制开关仅用于定位瓶颈，正式性能应使用“全部”。面三角化仅覆盖有效简单环，复杂自交面仍需后续兼容验证。

本页只加载用户选择的真实数据，不生成规则数据。普通示例默认使用 WebGL2，可切换 Canvas2D / WebGPU；正式 GPU 渲染已接入视口裁剪、微小 arc 和适用的大数据半像素过滤，导航按实际负载选择实时绘制或画面复用。默认测试页不会加载底图，避免把 MapLibre 的 WebGL 误认为本次渲染后端。

快照导航复用上一帧，平移可能暂时露出未绘区域，缩放时线宽也暂随快照缩放；停止后以原始几何重新绘制并恢复样式。这不是几何 LOD，也不是每帧完整重绘。编辑页有选中要素时不使用快照，保持顶点标记与原始坐标同步。

Canvas 屏幕过滤仅用于线与面描边：0.35 CSS px 的 arc 包围盒阈值按初始视图调整，顶点先投影到设备像素再截断至半像素；仅删除连续重复命令，全塌缩路径保留 0.1 设备像素短线。会改变小细节的显示，不是严格全精度显示；原生 dataset、面填充/洞、选择与编辑坐标不变。关闭两项可对照原始 GPU 路径。A/B 原始几何导航不含这两项过滤和快照；“过滤后暖重绘压测”使用当前固定视图和过滤后的路径缓存，不用快照，筛选准备耗时另列。
